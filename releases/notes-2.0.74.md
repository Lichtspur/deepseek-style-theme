## v2.0.74 — 集显上「飘动的正方形方块」修掉了

### 结论：不是粒子，也不是缩放，是 `mediump`

你截图里那些方块是**流体着色器的噪声格点**，因为那台机器（Intel Arc 130V 核显，ANGLE/D3D11）把 `mediump float` 当真 16 位浮点实现：

- ANGLE 走 D3D11 时 `mediump` → HLSL `min16float`；**Intel 核显原生就是 16 位浮点**，而桌面独显一般都把 mediump 提升成 32 位 —— 这就是同一份代码只在那台机器出问题的原因。
- 显示着色器的噪声是 `fract(sin(dot(st, vec2(12.9898,78.233))) * 43758.5453123)`，大约需要 24 位尾数才像噪声。16 位下哈希塌成一片片常数平台，于是**噪声格子本身**变成看得见的方块（这台机器上格子约等于屏幕宽 / 13）。
- 着色器里 `uv = rotate(uv, u_rotation * .5 * PI)` 让方块是斜的，`u_time` 让它飘 —— 和你拍到的完全一致。
- `dpr = 1.2396` 是无辜的（低于画布封顶 1.5，封顶没生效）。
- 顺带一个好消息：**能看到方块 = 那台机器 WebGL2 正常**（要是 WebGL2 不可用，画出来会是圆点+连线的粒子，而不是方块）。

### 改了什么
`precision mediump float;` → `precision highp float;`，FLOW_SHADER 与 DISPLAY_SHADER 各一处，别的一个字符没动。

- ES 3.00（WebGL2）**强制**片元着色器支持 `highp`，所以凡是能跑这个背景的引擎都安全。
- 在把 mediump 提升为 32 位的 GPU 上，这个改动是**空操作** —— 你现在这台机器的观感不会变。
- 因为三段 GLSL 一直声明为「上游逐字节副本」，这次把**唯一一处改动写进了署名文件**（`THIRD-PARTY-NOTICES.md`、README 两处、`lib/client.js` 头部注释），上游 MIT 归属与许可原文不变。

### 怎么复验
在那台机器上装 2.0.74，然后随便看一眼背景；也可以在控制台确认构建标记：

```js
window.__dshomeBuild   // 期望：2.0.74 highp-noise
```

方块应当消失、回到平滑洗色。如果还有方块，把 `renderer` 与控制台报错发我——那就是第二条路径（8 位、1/4 分辨率流场的量化），修法不同（把流场提到 1/2 分辨率或改用 `RGBA16F`）。

### 没动的东西（等你点头）
- `u_pixelRatio` 仍是**未封顶的真实 DPR**，而画布后备尺寸按**封顶 1.5** 算。DPR > 1.5 的机器上噪声尺度会比设计值小三分之一，也就是各机器观感略有差异。统一它会让高 DPR 机器的噪声**变大一点**，会改动你现在这台的样子，所以我留着没碰。
- npm 还是 `1.43.12`：插件市场的一键安装指向 npm，所以市场现在还在旧版本。

### 退路
