## v2.0.82 — 恢复对话框悬停的「放大 + 倾斜」（白磨砂同样生效），横向裁切扩到整个会话列

**你报回来的两件事，一件是我的错，一件还没结案。**

### 1. 「鼠标放在对话框上，放大和倾斜没了」= 2.0.79 的修法造成的；「白磨砂也要有」= 另一道旧闸门

2.0.79 为了切断一条自激回路做了两件事，两件都矫枉过正：

1. `TILT_SCALE: 1.01 → 1` —— **放大（抬升）被删掉了**；
2. 把 `input / textarea / [contenteditable]` 也列入"不能压在动面上的控件"——**输入框几乎盖满整张卡片**，把它排除，等于让倾斜在"鼠标放到对话框上"这个它唯一存在的姿势里**永不触发**。

两条同因：为了杀掉回路，把效果本身删了。这是修法造成的缺陷，不是错觉。

### 本版改法（保留效果，切断回路）

- **抬升回来**：`TILT_SCALE` 恢复 `1.01`；
- **输入框上可以倾斜**：`TILT_CONTROLS` 只留 `button / [role=button] / a[href] / [class*="andle" i]`。倾斜是**带着输入框一起动**的，指针不会因此掉出输入框；
- **滞回取代"越界即释放"**：指针进入控件时**冻结当前角度**——不重画、不回弹、不重新武装；回到卡片空白处再续；只有指针**离开卡片自己的矩形**才释放，且释放后 `TILT_COOLDOWN_MS = 200` 内不再重新进入。那条回路需要"释放"来喂它，而指针静止时倾角现在是**死的**；
- **白磨砂也一样有**：原先 `paint` / `onOver` 各有一道"不是液态就早退"的闸门（当时的理由是白磨砂保持逐像素不变），结果白磨砂用户永远看不到这个效果。闸门拆掉，并且**运动自带过渡** `TILT_TRANSITION`（值与原液态样式表里那条相同，随内联 transform 一起清掉）——配方少一条 `transition: transform` 也不会硬跳；
- **诊断**：`window.__dshomeTilt()` → `{ recipe, leaning, frozen, engagements, sinceRelease }`。两套配方现在都该倾斜；`engagements` 一直是 0 才说明守卫有问题。

### 2. 按钮跳动：本版补全了「横向滚动条」这一类的覆盖面

机制只需要**一个** `overflow-y: auto` 的容器（另一轴按 CSS 规则计算成 `auto`，于是能长出横向滚动条）+ 一个**悬停时变宽的子孙**：滚动条占掉 ~8px 高度 → 固定在下面的对话框整体上移 8px → 指针落到别的元素上 → 变宽的东西收回去 → 滚动条消失 → 落回来。首次报告点名的是消息列，2.0.78 只裁了它；**同样的 8px 台阶可以来自对话框自己的容器**（`composerSeat`）或转写区（`viewArea`）。本版把裁切扩成：

```css
[class*="scrollBody"],[class*="composerSeat"],[class*="viewArea"]{overflow-x:clip}
```

弹到 `<body>` 的浮层不受影响；代码块自己的横向滚动也不受影响。

**这一条我没有拿到你那台机器的数据，所以不敢说结案。** 如果还跳，请把现场探针跑一次（`tools/symptom-probe.js`，贴进控制台即可，19 项自测全绿）：

```js
__dshomeDiag.run(30)      // 鼠标停在发送按钮上，等它跑完，把结果贴回来
__dshomeDiag.tilt(false)  // 一行对照：冻结倾斜之后还跳吗
__dshomeDiag.clip(true)   // 一行对照：强制裁切之后还跳吗
```

`run(30)` 会**同时**采样三件事：GPU 状态（fps / context lost / `gl.getError()` / 画布尺寸抖动）、光标下的逐字段 diff（谁的 `box / transform / padding / margin` 在动、动了几 px、多快）、以及每个横向溢出容器及其超宽子元素。有了它，下一次就是定点修，不用再猜。
