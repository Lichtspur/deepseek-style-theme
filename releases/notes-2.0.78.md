## v2.0.78 — 结案：「按钮跳动 + 底部滑块闪」是横向滚动条引起的，已断链

你观察到的现象（鼠标在对话框右端移动 → 两颗按钮观感来回跳、底部滑块一闪一闪）这一版**找到真凶并掐断**。结论：**不是主题的倾斜，是产品的悬停操作栏把消息行撑出了横向滚动条。**

### 定位链（真机采样，逐步可复现）

1. **横向溢出**：会话滚动区 `wSkVaW_scrollBody` 的 `scrollWidth 917 > clientWidth 891`，越界元素是消息行的 `span._bubble_*` —— 产品在**悬停消息**时展示的操作栏，把那一行撑得比列还宽；
2. **8px 滚动条**：横向溢出 → 生成一条细横向滚动条 → 同一滚动区的 `clientHeight 842 → 834`（正好 8px）；
3. **对话框上移**：对话框固定在这个滚动区下方 → 卡片 `top 699 → 691`（−8px，与滚动区高度**严格同步**，日志里一一对应）；
4. **指针被"偷"**：上移 8px 后指针落到另一个元素上 → 操作栏收起 → 溢出消失 → 滚动条消失 → 对话框落回 → 回到第 1 步。

**~5Hz 两态自激** —— 你看到的"跳"和"滑块闪"就是这个环的两个投影。

### 被排除的嫌疑人（都有数据）

- **我们的「对话框悬停倾斜」**：`transform` 不参与布局，**不可能**改变任何元素的 `contentRect`；它对几何的全部影响是 ±1–3px 与卡片 757↔765 的视觉宽度，与那 8px 的节奏也不同步。
- **better-sidebar**：该页面上 `[data-dsh-center-col]` 与 `--dsh-sidebar-height` 都不存在（`n/a` / `-`），它的中心列同步没有参与。

### 处置

给会话滚动区加 `overflow-x: clip`（守护补丁块：锚点 `.wSkVaW_scrollBody`，规则用 `[class*="scrollBody"]` 子串匹配，散列类改名也不会静默失效）：

- 横向不再是可滚动方向 → **不产生滚动条** → 那 8px 不存在 → 闭环断开；
- 代码块自己的横向滚动条不受影响（它们各有各的容器）；
- 代价：超出列宽的部分会被**裁掉**而不是可滚动 —— 在聊天列里这是更小的恶（那个操作栏本来也不该溢出列宽）。

**溢出的根因在产品侧，值得上报**（这是产品的悬停操作栏布局，不是插件能"修"的）。

### 怎么复验

装上后回到原来那两颗按钮附近移动鼠标：抖动与滑块应当消失。控制台确认版本：`window.__dshomeBuild` → `2.0.78 no-sideways-scroll`。若还在跳，把控制台里 `[class*="scrollBody"]` 的 `scrollWidth/clientWidth` 发我 —— 那说明还有第二个溢出源。
